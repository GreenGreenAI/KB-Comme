# 대표 데모 — 한 문장이 두 숫자를 반대로 움직인다

말로 검증한 것이 아니라 실제 응답에서 뽑은 값이다. 커밋 `66c5322`,
기준일 `2026-08-02`, 환율 스냅샷 `ECOS_USD_KRW`(현재 1,441.1원).

## 왜 이 시나리오인가

이 제품의 주장은 「환위험을 한 번 더 분석한다」가 아니라 **환노출과 결제일 자금
공백을 함께 본다**는 것이다. 두 문장짜리 대화가 그 주장을 한 화면에서 증명한다 —
수입 거래 하나를 더하면 **환위험은 줄고 자금 공백은 생긴다.** 방향이 반대다.

## 입력

브라우저에서 그대로 칩니다. 예시 칩을 눌러도 됩니다.

```text
1턴   10월 24일에 수출대금 10만 달러 받기로 했어요
2턴   8월 25일에 수입대금 6만 달러도 나가요
```

2턴은 되묻기 없이 바로 반영된다. 방향이 다르므로 「새 거래인가 수정인가」를
묻지 않는다 — 같은 방향으로 금액만 다르게 말하면 그때는 묻는다.

## 화면에서 움직이는 것

| | 1턴 | 2턴 | |
|---|---:|---:|---|
| 거래 순노출 | **100,000** | **40,000** | 수입이 상쇄 |
| 환율 영향 (1,338.39원일 때) | **10,271,000원 덜 받음** | **4,108,400원 덜 받음** | 60% 감소 |
| 자금 공백 | 0 | **60,000** | 8월에 없던 부담이 생김 |
| 기간 상쇄 | 0 | 60,000 | 전 기간으로는 상쇄 |
| 실제로 덮이는 금액 | 0 | **0** | 수취가 두 달 늦어 자금으로는 못 덮음 |

한 문장으로 **환위험은 6할 줄었는데 8월에 6만 달러가 모자라게 됐다.** 엑셀로
환노출만 보던 회사가 놓치는 것이 정확히 이 자리다.

## 날짜만 바꾸면 정반대가 된다

같은 금액, 수입 결제일만 12월 20일로(수출 수취 뒤로) 옮긴 경우다.

| | 수입 8/25 (먼저) | 수입 12/20 (나중) |
|---|---:|---:|
| 거래 순노출 | 40,000 | 40,000 |
| 자금 공백 | **60,000** | **0** |
| 실제로 덮이는 금액 | **0** | **60,000** |

**환노출은 같고 자금 사정은 정반대다.** 총액만 보는 계산으로는 두 경우가 구별되지
않는다. 시점을 함께 세는 것이 왜 필요한지를 두 줄로 보여줄 수 있는 대비다.

## 이어서 보여줄 것

- **「받을 수 있는 지원제도가 있나요」** — 기업규모·신용을 되묻고, 답하면 K-SURE
  세 제도를 판정한다. 규칙이 부족한 사실을 이름으로 물으므로(등급, 자금 용도,
  선적일) 답할수록 판정이 닫힌다.
- **「왜?」** — 각 판정이 무엇을 확인했는지 말한다. 앞 문장의 주제를 잇는다.
- **「환변동보험이 뭐야?」** — 제도 설명은 아직 다루지 않는다고 말한다. 근거 없는
  설명을 지어내지 않는다는 것을 보여주는 자리다.

## 주의

- **보유 외화를 넣어도 거래 순노출은 움직이지 않는다.** 그 값은 Σ수취 − Σ지급이고
  보유잔액은 자금 공백 쪽을 움직인다(60,000 → 40,000). 두 숫자가 서로 다른 입력에
  반응한다는 것 자체가 설명거리이지, 하나가 고장 난 것이 아니다.
- 화면은 **다시 계산한 결과**를 보여주고, 1턴과 2턴을 나란히 놓는 전후 비교는
  Decision Delta(PR #59)가 담당한다.
- 손실 금액은 환율 스냅샷에 따라 달라진다. 위 값은 현재 1,441.1원 기준이다.
