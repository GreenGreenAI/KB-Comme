# TradeFlow 차별화 전략: 답을 바꾸는 조건을 보여주는 금융 의사결정 AI

## 1. 결정

TradeFlow는 환위험 분석 주제의 독점성을 차별점으로 삼지 않는다. 유사 서비스와 주제가
겹치더라도 사용자가 즉시 식별할 수 있는 고유 경험을 다음과 같이 정의한다.

> TradeFlow는 답만 제시하지 않는다. 무엇이 답을 바꾸는지 보여준다.

제품은 수출입 거래에서 자금 공백과 금융지원 후보를 계산한 뒤, 결과를 바꾸는 다음 정보,
정보 보완 전후의 판정 변화, 판단의 근거를 하나의 재현 가능한 상담자료로 제공한다.

## 2. 문제와 차별점

일반적인 환위험·무역금융 에이전트는 위험지표, 헤지안 또는 상품 후보를 결과로 제시한다.
이 방식만으로는 사용자가 결과를 신뢰하거나 실제 금융상담을 준비하기 어렵다.

TradeFlow는 결과와 함께 다음 세 가지를 제품화한다.

1. **Next Decisive Question**: 현재 결과를 바꾸는 다음 질문
2. **Decision Delta**: 정보를 보완하기 전과 후의 계산·판정 차이
3. **Decision Passport**: 사실·계산·규칙·출처·미확인 조건이 묶인 상담자료

핵심 차이는 추천 주제가 아니라 결정이 만들어지고 바뀌는 과정 전체를 보여준다는 점이다.

## 3. 대표 사용자 경험

### 3.1 입력

- 2026년 8월 25일 수입대금 USD 60,000 지급
- 2026년 10월 24일 수출대금 USD 100,000 수취
- 현재 외화잔액 미입력

### 3.2 최초 결과

```text
8월 25일 USD 60,000가 부족합니다.
부족 기간은 60일입니다.

이 결과를 가장 크게 바꾸는 정보는 현재 보유 외화입니다.
현재 보유한 USD가 있습니까?
```

### 3.3 정보 보완과 Decision Delta

사용자가 보유 외화 `USD 20,000`을 입력하면 전체 결과를 반복하지 않고 변경된 내용을
우선 표시한다.

```text
최대 부족액     USD 60,000 → USD 40,000
계산 근거       외화잔액 미반영 → USD 20,000 반영
다음 확인사항   은행 사전상담 여부
```

금융지원 후보에 대해서도 같은 방식을 적용한다.

```text
변경 전         조건부 후보
변경 원인       은행 사전상담 여부 미확인
사용자 답변     은행 사전상담 완료
변경 후         전문가 확인 대상
다음 행동       KB 상담자료 생성
```

### 3.4 Decision Passport

상담자료에는 결론만 넣지 않고 다음 항목을 함께 보존한다.

- 사용자가 확인한 거래 사실과 증거
- 자금 공백 계산식과 계산 버전
- 적용한 규칙 ID와 판정 상태
- 공식 출처, 기준일과 유효기간
- 아직 확인되지 않은 조건
- 최종 확인 권한을 가진 기관
- 변경 전후의 결정 이력

KB 담당자는 AI 문장을 신뢰하는 대신 재현 가능한 사실·계산·규칙·출처를 검토한다.

## 4. 기술적 토대

이 경험은 생성형 모델의 프롬프트만으로 구현하지 않는다.

| 계층 | 책임 |
|---|---|
| 거래 사실 계층 | 사용자 입력, 문서 추출값, 회사·거래 범위와 증거를 구조화한다. |
| 결정론적 계산 계층 | 자금 공백, 순노출, 자연헤지와 만기상계를 계산한다. |
| 규칙 계층 | 지원 후보, 신고 가능성, 누락 조건과 권한 기관을 판정한다. |
| 변화 분석 계층 | 어떤 입력이 계산·판정·다음 행동을 바꾸는지 비교한다. |
| 근거 계층 | 규칙 버전, 공식 출처, 유효성, 충돌과 검토 상태를 보존한다. |
| 표현 계층 | LLM은 계산하거나 판정하지 않고 결정된 결과를 설명한다. |
| 인계 계층 | 원문 문서나 승인 주장을 제외한 감사 가능한 상담자료를 생성한다. |

동일 입력과 동일 규칙 버전은 동일한 결정 결과를 재현해야 한다. 규칙이나 검증 suite가
변경되면 기존 전문가 승인은 stale이 되며, 상담자료도 사용한 버전을 명시해야 한다.

## 5. 제품 요구사항

### 5.1 결과 카드

모든 주요 결과 카드에는 다음 항목을 제공한다.

- 결과: 언제 얼마가 부족하거나 어떤 후보 상태인지
- 이유: 사용된 거래 사실과 계산·규칙
- 결정 변경점: 결과를 바꾸는 확인 가능한 입력
- 다음 행동: 사용자가 답하거나 준비할 자료
- 근거 보기: 공식 출처와 검토 상태

### 5.2 다음 질문 우선순위

질문은 단순한 빈칸 순서가 아니라 다음 기준으로 정렬한다.

1. 계산 결과를 바꾸는 정보
2. 금융지원 후보 상태를 바꾸는 정보
3. 안전 경고 또는 신고 가능성을 바꾸는 정보
4. 상담자료의 완성도를 높이는 정보
5. 결과에 영향을 주지 않는 설명용 정보

하나의 답으로 여러 후보가 달라진다면 그 질문을 먼저 제시한다. 답변을 받기 전에는
가능한 결과를 확정적으로 표현하지 않는다.

### 5.3 변경 비교

사용자가 정보를 수정하거나 보완하면 다음 항목의 전후 차이를 구조화해 반환한다.

- 자금 공백의 금액·날짜·기간
- 순노출과 자연헤지
- 후보의 추가·제거·상태 변경
- 새로 해소되거나 발생한 누락정보
- 추가·제거된 다음 행동과 필요서류
- 변경에 사용된 근거

## 6. 범위와 안전 원칙

TradeFlow는 다음을 주장하지 않는다.

- 금융기관의 대출·보증·보험 승인
- 규제기관을 대신한 최종 신고 판정
- 지원하지 않는 결제방식이나 통화의 임의 변환
- LLM이 생성한 금액·자격·법률 결론
- 사용자 동의 없는 상담자료 전송

규칙팩이 독립 도메인 전문가 승인을 받기 전에는 `후보`, `조건부`, `전문가 확인 필요` 상태를
유지한다. 이 거버넌스 제약도 Decision Passport에 표시한다.

## 7. 30초 데모

1. 수입 USD 60,000과 수출 USD 100,000의 결제일을 입력한다.
2. TradeFlow가 8월 25일의 USD 60,000 자금 공백을 표시한다.
3. `무엇이 결과를 바꾸나요?`를 선택한다.
4. 서비스가 보유 외화를 가장 영향력 있는 다음 질문으로 제시한다.
5. USD 20,000을 입력하면 부족액이 USD 40,000로 변한 부분만 강조한다.
6. 은행 사전상담 여부를 확인해 보증 후보 상태의 변화를 보여준다.
7. 사실·계산·규칙·출처·미확인 조건이 포함된 KB 수동 상담자료를 생성한다.

발표 문구는 다음으로 통일한다.

> TradeFlow는 답만 하지 않습니다. 무엇이 답을 바꾸는지 보여줍니다.

## 8. 성공 기준

| 지표 | 의미 |
|---|---|
| Decision Delta 정확도 | 입력 변경이 영향을 준 결과만 정확하게 표시하는 비율 |
| 질문 효율 | 유효한 결과까지 사용자가 답한 질문 수 |
| Missing-input Closure | 답변한 필드가 이유 없이 다시 질문되지 않는 비율 |
| 계산 재현성 | 동일 입력·버전에서 동일 구조화 결과가 생성되는 비율 |
| 근거 완성도 | 판정에 규칙 ID·출처·버전·검토 상태가 포함된 비율 |
| 상담자료 완성도 | KB 담당자가 추가로 요구한 사실·서류의 수 |
| 과신 방지율 | 미확인 조건을 확정 판정으로 승격하지 않은 비율 |

초기 릴리스에서는 모든 critical 고객 과업 통과, 계산 재현성 100%, 과신 방지율 100%를
비보상형 게이트로 사용한다.

## 9. 구현 및 검증 상태

2026-08-01 기준 세 기능을 실제 서비스 흐름에 연결했다.

| 기능 | 구현 결과 | 검증 근거 |
|---|---|---|
| Next Decisive Question | 자금 공백이 있고 외화잔액이 미입력되면 이를 최우선으로 질문하며, 이후에는 실제로 차단한 판정 수가 많은 질문부터 정렬한다. | 계약 테스트와 브라우저 입력 테스트 |
| Decision Delta | 로그인한 동일 조직의 이전 저장 분석과 새 분석을 비교해 자금 공백·순노출·자연헤지·만기일치·지원 후보 상태·다음 행동·필요서류와 해결된 질문을 반환한다. 탈락 목록으로 이동한 후보도 실제 상태를 보존한다. | 계약·tenant 경계 통합 테스트와 UT16 |
| Decision Passport | 사실·계산·규칙·출처에 다음 질문과 Decision Delta를 더해 수동 KB 상담자료로 생성한다. 자동 전송과 원문 문서 포함은 계속 금지한다. | handoff 통합 테스트와 UT16 |

대표 시나리오의 실제 측정 결과는 `USD 60,000 → USD 40,000`, 수출신용보증 후보
`conditionally_eligible → expert_confirmation_required`였으며, 동일 변화 기록이 Decision
Passport에 보존됐다. 고객 과업 벤치마크는 16/16 과업, 53/53 구조화 검증을 통과했고
Playwright 브라우저 E2E 3/3을 통과했다.

현재 KB 데이터나 API를 사용하지 않는다. 은행 연계는 `bank_consultation.v1` 어댑터 경계 뒤에
남겨두고, 사용자 동의를 받은 수동 자료 생성까지만 제품 범위로 유지한다.
