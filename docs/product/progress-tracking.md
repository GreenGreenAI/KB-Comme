# TradeFlow 통합 프로그레스 트래킹

## 1. 목적

이 문서는 TradeFlow의 기획, 설계와 구현 진척을 한 화면에서 확인하는 기준 대시보드다.
상세 판단과 근거는 아래 세 문서에서 관리한다.

- [기획 프로그레스](planning-progress.md)
- [설계 프로그레스](design-progress.md)
- [구현 프로그레스](implementation-progress.md)

현재 제품 정의는 `수출입금융 실행 플랫폼`이 아니라, 반복 수출입 제조기업이 자금 공백과
환위험을 계산하고 금융기관 상담에 필요한 판단 근거와 자료를 준비하는 의사결정
워크스페이스다.

## 2. 상태 판정 규칙

| 상태 | 의미 | 필요한 근거 |
|---|---|---|
| 완료 | 합의된 완료 기준을 현재 산출물이 충족 | 승인 문서 또는 실행 코드와 직접 검증 |
| 부분 완료 | 핵심 일부는 동작하지만 범위·데이터·운영 조건이 남음 | 완료된 부분과 남은 조건을 함께 명시 |
| 차단 | 팀 내부 구현만으로 완료할 수 없음 | 외부 결정권자, 데이터, 계약 또는 파일럿 필요 |
| 예정 | 승인된 범위지만 아직 착수하지 않음 | 선행조건과 목표 milestone 명시 |

문서가 존재한다는 이유만으로 `완료`로 올리지 않는다. 구현 항목은 테스트, 벤치마크 또는
재현 가능한 운영 절차가 있어야 완료다. 외부 승인 대기는 코드 완료율에 포함하지 않는다.

## 4. Milestone 판정

| Milestone | 목표 | 상태 | 종료 조건 |
|---|---|---|---|
| M0 문제·고객 정의 | 핵심 고객과 해결할 과업 합의 | 완료 | 반복 수출입 제조기업과 상담 전 의사결정 범위 문서화 |
| M1 Decision Workspace MVP | 분석부터 결과 변경·근거 확인까지 연결 | 완료 | Next Decisive Question, Decision Delta, Passport와 테스트 |
| M2 수동 상담 폐쇄 루프 | 패킷 전달 이후 상담 결과까지 추적 | 완료 | 허용 상태 전이, tenant 저장, 사용자 기록 표시, E2E |
| M3 운영 신뢰성 | 규칙과 모델의 운영 승격 | 차단 | 독립 도메인 전문가 승인과 실제 호가 검증 |
| M4 고객 효용 검증 | 실제 기업·RM이 과업을 완료 | 차단 | 파일럿 성공지표와 질적 평가 확보 |
| M5 금융기관 연계 | 실제 KB 또는 금융기관 채널 송수신 | 예정 | 공식 계약, sandbox, 인증, 멱등성과 접수상태 계약 |

## 5. 최우선 순서

1. 실제 고객·RM 파일럿 설계와 모집 조건을 확정한다.
2. 상담에 필요한 희망 한도, 무역실적, 거래상대방 신용 근거의 입력 계약을 구현한다.
3. 독립 도메인 전문가에게 두 규칙팩 검토 패킷을 전달하고 결과를 기록한다.
4. `country_risk`, `buyer_credit`, `lc_review`, `support_policy_finance` 순서를 고객 증거로 재결정한다.
5. KB API는 공식 인터페이스가 확보될 때까지 중립 provider 경계 밖에서 추정하지 않는다.

## 6. 갱신 규칙

- 기능 PR은 영향받는 추적 ID, 상태 변경, 검증 결과를 함께 갱신한다.
- 매주 한 번 수치와 외부 차단 조건을 확인한다.
- 제품 범위 변경은 기획 문서를 먼저, 계약 변경은 설계 문서와 ADR을 먼저 갱신한다.
- 테스트 수치는 실제 재실행 결과만 기록한다.
- 완료 항목이 회귀하거나 근거가 만료되면 즉시 `부분 완료` 또는 `차단`으로 내린다.
