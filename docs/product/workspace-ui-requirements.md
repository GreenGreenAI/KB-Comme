# 거래 Workspace와 AI 코파일럿 요구사항

## 목적

이 문서는 현재 대화·구조화 분석 2열 화면을 거래 중심 업무 Workspace로 발전시키기
위한 제품 요구사항과 역할 간 인수 조건을 정의한다.

대상 독자는 지식·도메인 담당(역할 A), 아키텍처·런타임 담당(역할 B), 제품
검토자다. 역할 A는 화면에 필요한 의미와 근거 계약을 제안하고, 역할 B는 이
요구사항을 검토한 뒤 별도 구현 PR에서 사용자 경험과 기술 구현을 담당한다.

## 제품 원칙

TradeFlow는 대화 내용을 답변하고 소멸시키는 챗봇이 아니다. 수출입 거래를
구조화하고 분석 결과와 다음 행동을 지속해서 관리하는 업무 시스템이다.

- 모든 입력, 분석, 판정과 실행 항목은 채팅 세션이 아니라 `TradeProgram` 또는
  `TradeCase`에 귀속한다.
- 결정론 계산과 규칙 판정 결과를 화면의 기준 데이터로 사용한다.
- AI는 누락 정보 수집, 결과 설명, 탐색과 초안 작성을 돕는 코파일럿이다.
- AI 설명은 계산값, 판정 상태, 근거, 검토 필요 여부를 변경할 수 없다.
- 사용자는 결과뿐 아니라 기준일, 데이터 최신성, 적용 규칙과 근거를 확인할 수
  있어야 한다.
- 정보 부족, 분석 불가와 오류를 성공 결과처럼 표시하지 않는다.

## 사용자와 핵심 과업

### 기업 사용자

1. 수출·수입 거래를 등록하고 하나의 프로그램으로 연결한다.
2. 시점별 외화 지급·수취, 자금 공백과 순노출을 확인한다.
3. 규정, 금융·보험·지원제도 후보와 제외 사유를 확인한다.
4. 필요한 서류, 미충족 조건, 다음 행동과 기한을 관리한다.
5. 불확실하거나 고위험인 항목의 `review_required` 상태와 사유를 확인한다.

## 화면 정보구조

MVP는 대회용 [MVP 아키텍처](../specifications/mvp-architecture.md)의 단일 기업
Web 범위 안에서 다음 두 업무 화면을 제공한다. 두 화면은 별도 URL일 수도 있고
하나의 화면 안에서 상태 전환으로 구현할 수도 있다. 라우팅 방식은 역할 B가 정한다.

### 1. 거래 목록

- 수출·수입 방향, 거래처, 통화, 금액, 결제 예정일과 현재 상태
- 프로그램, 위험·검토 상태와 데이터 기준일
- 방향, 상태, 통화, 기간과 검토 필요 여부 필터
- 신규 거래 등록과 기존 TradeProgram 연결 진입점

### 2. TradeProgram 상세

- 연결된 수출·수입 거래와 지급·수취 타임라인
- 시점별 Cashflow, 자연헤지 가능액, 자금 공백과 잔여노출
- 프로그램에 속한 거래의 경고와 실행 항목
- 계산 기준, 스냅샷과 분석 재실행 상태
- 선택한 TradeCase의 거래조건과 입력 사실
- 계산된 노출, 환율 시나리오와 헤지 비교
- 규정·자격 판정의 후보·제외·정보 부족·검토 필요 구분
- 기관, 상품, 필요서류, 다음 행동, 기한과 근거
- `review_required` 사유

### 내장 AI 코파일럿

AI 코파일럿은 전체 화면을 대체하지 않고 현재 선택한 프로그램이나 거래의 문맥에서
다음 기능을 제공한다.

- 누락된 필수 입력 질문
- 계산·판정 결과의 쉬운 설명
- 특정 후보의 포함·제외 사유와 근거 탐색
- 실행 항목, 상담 질문과 체크리스트 초안 작성
- 사용자가 요청한 화면 또는 거래로 이동 지원

AI 답변의 수치, 상태와 출처는 화면의 구조화된 결과로 다시 확인할 수 있어야 한다.
대화에서 받은 유효한 수정값은 확인 절차를 거쳐 거래 데이터에 저장하며, 대화 기록
자체를 업무 데이터의 유일한 저장소로 사용하지 않는다.

MVP에서는 현재 브라우저 세션의 구조화 상태에 반영하는 것으로 충분하다. 서버
영속성과 인증이 도입된 뒤에는 같은 원칙을 영구 거래 레코드에 적용한다.

### MVP 이후 집계·검토 화면

다음 화면은 제품 방향에는 포함하지만 대회 MVP의 인수 조건에서는 제외한다.

- 포트폴리오 대시보드
- 전체 거래 실행 Queue
- RM Console과 Review Service
- Admin Console
- 인증된 영속 거래 보관함

## 구조화된 결과 표시 계약

프론트엔드는 `DecisionPacket`을 다음과 같이 투영한다. 필드의 의미와 LLM 변경
제한은 [공유 계약](../specifications/contracts.md)을 따른다.

| 화면 요소 | 기준 필드 | 표시 요구사항 |
|---|---|---|
| 분석 식별·기준 | `packet_id`, `schema_version`, `as_of` | 결과 상세에서 조회 가능 |
| 입력 사실 | `inputs` | 사용자 입력과 외부 근거 기반 사실을 구분 |
| 외화 노출 | `exposures` | 통화, 방향, 금액, 단위와 계산 기준 표시 |
| 판정 결과 | `decisions` | 후보·제외·정보 부족·전문가 검토 상태를 구분 |
| 다음 행동 | `actions` | 기관, 행동, 기한, 요건, 문서와 절차 표시 |
| 근거 | `evidence` | 출처, claim ID, 버전, 기준일과 최신성 표시 |
| 검토 게이트 | `review_required`, `review_reasons` | 숨기지 않고 주요 경고로 표시 |

화면은 다음 상태를 명시적으로 구분한다.

- 최초 로딩
- 데이터 없음
- 필수 입력 부족
- 분석 진행 중
- 분석 완료
- 일부 분석 실패
- 데이터 stale 또는 source unusable
- 전문가 검토 필요
- API·네트워크 오류와 재시도 가능 여부

## 역할 경계

### 역할 A: 지식·도메인

- 화면에 표시할 판정 의미, 분류와 근거 요구사항 정의
- `DecisionPacket`과 지식 계약의 예제 및 경계 사례 제공
- 규정·자격·필요서류 표현의 정확성 검토
- 확정 표현, 근거 누락과 LLM 월권 여부 검토

### 역할 B: 아키텍처·런타임

- 라우팅, 화면 구성, 상태 관리와 반응형 사용자 경험 구현
- API 연동, 로딩·오류·재시도와 캐시 정책 구현
- 접근성, 성능, 보안과 프론트엔드 테스트
- 구조화 결과와 코파일럿을 결합한 상호작용 설계

### 공동 검토

- API 또는 공유 계약 변경
- `DecisionPacket` 필드의 화면 투영
- 대표 사용자 흐름과 완료 조건
- 오류·정보 부족·검토 필요 상태의 사용자 표현

이 문서는 역할 B의 컴포넌트 구조, 상태관리 라이브러리, CSS 방식이나 배포 기술을
지정하지 않는다.

## MVP 수용 기준

다음 조건을 모두 만족해야 현재 2열 분석 화면을 TradeFlow Workspace MVP로 본다.

1. 사용자는 채팅을 거치지 않고 거래 목록에서 TradeCase를 열 수 있다.
2. 수출과 수입 거래를 하나의 TradeProgram에서 함께 확인할 수 있다.
3. Cashflow, 자연헤지, 자금 공백과 잔여노출이 메시지가 아닌 구조화된 영역에
   표시된다.
4. 판정 후보, 제외, 정보 부족과 전문가 검토가 시각적으로 구분된다.
5. 모든 판정에서 근거와 기준일로 이동할 수 있다.
6. 실행 항목에 기관, 행동, 기한, 미충족 요건과 필요서류가 보존된다.
7. stale·실패·일부 성공 상태가 정상 완료와 구분된다.
8. 코파일럿이 구조화 결과와 다른 수치·판정·근거를 확정적으로 제시하지 않는다.
9. 대표 수출·수입 연결 시나리오와 오류 상태를 기존 단위·통합 테스트에서
   검증한다. 브라우저 E2E는 별도 optional extra로 두며 MVP CI의 필수 조건으로
   추가하지 않는다.

## 구현 PR 인수 자료

역할 B의 구현 PR에는 다음 자료를 포함한다.

- 구현한 화면과 제외한 화면 목록
- 대표 수출·수입 연결 시나리오의 화면 캡처 또는 실행 영상
- API mock 또는 실제 응답과 `DecisionPacket` 투영 예제
- 로딩, 빈 상태, stale, 일부 실패와 전문가 검토 화면
- 단위·통합·사용자 흐름 테스트 결과
- 브라우저 E2E를 추가했다면 optional extra 실행 방법과 결과
- 남은 API 또는 계약 의존성과 후속 작업

## 범위 밖

- 이 문서 PR에서 프론트엔드 코드를 구현하는 것
- 은행 거래, 보험 가입 또는 외환 주문의 자동 실행
- RM Console, RM Review Service와 Admin Console
- 서버 영속 저장소, 인증과 조직별 권한
- 포트폴리오 대시보드와 전체 실행 Queue
- AI가 계산·규칙 결과를 덮어쓰는 기능
- 근거 없는 환율 예측이나 승인 가능성 확정
- 역할 B의 세부 기술 스택을 역할 A가 결정하는 것

## 미결정 사항

- 대시보드의 기본 집계 기간과 기준 통화
- 거래 수정 후 분석을 자동 재실행할지 명시적으로 요청할지 여부
- 코파일럿 대화와 감사 이력의 보존기간
- 서버 영속 저장소와 인증을 어느 제품 단계에서 도입할지 여부
