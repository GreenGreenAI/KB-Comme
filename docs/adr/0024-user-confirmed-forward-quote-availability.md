# ADR-0024: 사용자 확인 선물환 호가 기반 가용성

- 상태: 제안
- 날짜: 2026-07-28
- 관련: ADR-0004, 이슈 #13, PR #19

## 배경

헤지비율 계산기는 `AVAILABLE` 상태이며 `contract_rate`와 `cost_rate`가 있는
`HedgeMeasure`를 요구한다. 그러나 공개 환율과 금리로 계산한 이론 선물환율은
특정 기업이 은행에서 실제로 제시받은 계약 조건이 아니다. 이론값을
`contract_rate`로 사용하면 모델 추정이 관측된 은행 호가처럼 보이게 된다.

반대로 기업이 실제로 받은 호가는 해당 기업·통화·만기·금액에 한정된 실행 가능
조건이다. 다만 사용자 입력이라는 이유만으로 범위와 유효시간을 확인하지 않고
가용으로 만들면 다른 거래나 만료된 가격에 잘못 적용될 수 있다.

## 고려한 선택지

1. 공개 금리로 이론 선물환율을 계산해 계약환율로 사용한다.
2. K-SURE 환변동보험 가격만 먼저 지원한다.
3. 사용자가 실제로 제시받은 기업별 호가를 구조화하고 정확한 적용 범위와
   유효시간을 만족할 때만 가용으로 판정한다.
4. MVP에서 헤지비율 계산을 제외한다.

## 결정

3번을 선택한다.

- 입력은 `UserForwardQuote`로 구조화한다.
- 다음 값은 모두 필수다.
  - 호가 ID, 제공기관 ID, 회사 ID
  - 호가가 포괄하는 거래 ID
  - 기준·상대 통화와 매수·매도 방향
  - 최대 명목금액, 계약환율, 명시적 비용률
  - 결제일, 호가 시각, 유효 종료 시각
  - 사용자 명시적 확인
- 출처 ID는 `USER_QUOTE:{provider_id}:{quote_id}`로 생성한다. 사용자가 임의의
  공식 출처 ID를 부여할 수 없다.
- 증거 역할은 가격 주장에 맞는 `market_data`로 유지하되
  `user_confirmed_provider_quote`로 분류하여 공개 시장 데이터와 분리한다.
- 호가가 있다는 사실만으로 자동 선택하지 않는다. 사용할 호가 ID가 명시적으로
  선택되어야 한다.
- 다음 조건을 모두 만족할 때만 `AVAILABLE`이다.
  - 회사와 거래 범위가 프로그램과 일치
  - 현재 엔진 범위인 단일 외화·원화 상대 호가
  - 매수·매도 방향이 순외화 노출 방향과 일치
  - 명목금액이 순외화 노출 이상
  - 결제일이 프로그램의 마지막 순노출 만기와 일치
  - 평가 시각이 호가 시각 이상이며 유효 종료 시각 이하
- 미래 시각, 다른 회사, 알 수 없는 거래는 계약 오류로 중단한다.
- 만료·범위 불일치·미선택 호가는 가격이 남아 있더라도 옵티마이저에 전달하지
  않는다.
- 사용자 확인 호가는 은행 API 검증이나 공개 시장 데이터가 아니다. 이 한계는
  evidence payload와 응답에 보존한다.

## 연결 거래의 해석

동일 외화의 수입과 수출 거래가 연결된 경우 전체 거래의 순노출을 마지막
결제일에 헤지하는 호가를 허용한다. 예를 들어 수입 USD 60,000과 수출
USD 100,000이면 USD 40,000 매도 호가가 대상이다.

이 판정은 앞선 수입 지급시점의 자금 부족을 없애지 않는다. Cashflow의
`peak_funding_gap`과 만기 불일치는 별도로 유지한다.

## 역할 경계

역할 A는 다음을 제공한다.

- `UserForwardQuote`
- `UserQuoteHedgeAvailabilityService`
- 호가 evidence와 `HedgeMeasure` 변환
- fail-closed 정책 테스트

역할 B는 다음을 연결한다.

- API·화면의 호가 입력과 명시적 선택
- 서비스가 반환한 measure를 오케스트레이터에 전달
- 호가 evidence를 최종 응답과 감사 기록에 포함
- 만료 호가 재입력 요청과 복수 호가 비교 UI

## 결과

헤지비율 계산은 공개 데이터로 만든 가상 계약가격이 아니라 기업이 실제로 받은
활성 호가를 사용한다. 호가가 없거나 만료됐거나 적용 범위가 맞지 않으면
`insufficient_information`, `conditional` 또는 `unavailable`로 남으며 계산기는
실행되지 않는다.

## 검증

- 선택된 활성 호가의 `AVAILABLE` 판정과 출처 보존
- 미입력·미선택·만료 상태 구분
- 회사·거래·통화·방향·만기·명목금액 불일치 차단
- 미래 호가와 분석일 불일치 fail-closed
- 연결 수입·수출의 잔여 순노출 판정
- 중복 호가 ID와 존재하지 않는 선택 ID 차단
