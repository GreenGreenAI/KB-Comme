# ADR-0007: LLM 실행 경계와 DecisionPacket

- 상태: 제안(Role B 승인 대기)
- 날짜: 2026-07-27
- 관련: ADR-0002, ADR-0003, ADR-0006, MVP 아키텍처 정의

## 배경

금액 계산, 규칙 판정, 출처 상태, 검토 필요 여부를 LLM이 직접 생성하면 같은 입력에도
결과가 달라질 수 있고 근거를 재현하기 어렵다. 반대로 결정론 엔진의 결과만 그대로
노출하면 사용자가 판단 근거와 다음 행동을 이해하기 어렵다.

따라서 결정론 계층과 LLM 합성 계층 사이에 명시적인 불변 계약이 필요하다.

## 결정

### 1. 계산과 판정은 LLM 밖에서 수행한다

다음 작업은 결정론 코드, 규칙 엔진 또는 검증된 외부 도구가 담당한다.

- 현금흐름, 익스포저, 비용과 수익 등 수치 계산
- 자격, 제한, 예외, 출처 상태와 신선성 판정
- 근거 충족 여부와 `review_required` 결정
- 정책상 필요한 조건과 누락 필드 생성

LLM은 이 결과를 재계산하거나 새로운 판정으로 대체할 수 없다.

### 2. DecisionPacket을 유일한 합성 입력으로 사용한다

`DecisionPacket`은 다음을 포함하는 버전 계약이다.

- 패킷 ID, 스키마 버전, 기준일
- 정규화된 입력 사실
- 결정론적 익스포저와 계산 결과
- 규칙별 판단 상태와 요구사항
- 근거 식별자
- 검토 필요 여부와 사유

케이스별 판정이 추가된 schema `1.1`부터 `packet_id`는 program ID·기준일과 패킷
입력/분석 내용의 SHA-256 지문을 포함한다. 같은 프로그램과 기준일이라도 assertion,
근거 또는 판정이 달라지면 다른 packet ID를 가져야 하며, 동일 분석의 재실행은 같은
ID를 반환한다.

근거의 `generated_at`은 패킷 계보와 지문에 포함되므로
`EvidenceDescriptor` 생성자가 반드시 명시적으로 받아야 한다. 현재 시각을 암묵적
기본값으로 사용하면 동일 입력의 재실행마다 지문이 달라지므로 허용하지 않는다.

파이프라인은 `analyze_packet`으로 결정론 분석과 패킷 생성을 완료한 뒤 합성 계층에
전달한다. 합성 계층은 원래 사용자 입력이나 외부 출처를 직접 조회해 패킷을 우회하지
않는다.

### 3. LLM은 설명과 표현만 담당한다

허용 범위는 다음과 같다.

- 패킷 내용을 사용자 언어와 수준에 맞게 설명
- 이미 존재하는 판단 근거와 조건을 요약
- 패킷에 명시된 검토 사유와 다음 확인 항목을 읽기 쉽게 배열

금지 범위는 다음과 같다.

- 수치 재계산, 반올림 또는 추정치 생성
- 판단 상태 변경이나 불확실성 완화
- 패킷에 없는 출처, 조건, 상품 또는 정책 생성
- `review_required`와 검토 사유 제거

### 4. 구조화된 합성 결과를 결정론적으로 검증한다

`SynthesisResult`는 설명문과 함께 판단 상태, 수치 주장, 근거 ID, 검토 상태를
구조화해 반환한다. `validate_synthesis`는 다음을 거부한다.

- 패킷과 다른 판단 상태 또는 일부 판단 누락
- 패킷에 없거나 값이 달라진 수치 주장
- 존재하지 않는 근거 ID
- 변경되거나 누락된 검토 필요 여부와 사유

검증 실패 결과는 사용자 응답으로 승격하지 않는다. 원본 `DecisionPacket`을 기반으로
결정론적 대체 응답을 제공하거나 사람 검토로 보낸다.

## 결과

- LLM 교체와 프롬프트 변경이 계산 및 정책 판정에 영향을 주지 않는다.
- 생성 설명은 비권위적 표현 계층으로 제한된다.
- 최종 권위는 결정론 결과와 사람 검토에 남는다.
- 새 LLM 기능은 패킷 필드와 검증 규칙을 먼저 확장해야 한다.

## 검증

- 상태 변경, 수치 변조, 근거 생성, 검토 상태 완화를 거부하는 단위 테스트를 둔다.
- 패킷 입력의 컨테이너 값이 불변 형태로 정규화되는지 확인한다.
- 전체 파이프라인 테스트에서 기존 결정론 결과가 유지되는지 확인한다.
