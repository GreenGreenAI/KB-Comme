# ADR-0028: 금융기관 중립 상담 인계와 KB 어댑터 경계

- 상태: 제안
- 날짜: 2026-07-31

## 배경

TradeFlow는 고객의 거래·자금공백·환위험·지원제도 판정을 은행 상담으로 이어야 한다. 그러나
현재 KB국민은행의 내부 상품, 고객별 한도·금리·신용등급 또는 접수 API 계약은 확보되지 않았다.
공개 웹 화면을 실행 API로 간주하거나 은행의 승인을 추정하면 서비스가 사실과 권한을 넘어서게
된다.

## 고려한 선택지

1. 핵심 도메인에 KB 상품과 화면을 직접 결합한다.
2. 연계 계약을 확보할 때까지 상담 기능 전체를 보류한다.
3. 금융기관 중립 패킷을 만들고 수동 인계를 기본 어댑터로 둔다.

1은 비공개 판단을 추정하게 만들고 교체 비용이 크다. 2는 이미 검증된 분석을 실제 상담으로
이어 주지 못한다. 3은 현재 가능한 가치를 제공하면서 실제 API가 생겼을 때 전송 구현만 교체할
수 있다.

## 결정

- 분석 결과에서 `bank_consultation.v1` 상담 패킷을 투영한다.
- 패킷은 거래, 순노출, 최대 자금공백, 지원·신고 판정, 다음 행동, 문서 체크리스트, 누락 정보,
  근거와 계산 버전을 포함한다.
- 원문 문서와 바이너리는 포함하지 않는다.
- 패킷 생성에는 로그인된 분석 이력과 명시적 목적 동의가 필요하다.
- 기본 상태는 `ready_for_manual_handoff`, 모드는 `manual_packet`이다.
- 이 상태는 다운로드 준비 완료를 뜻하며 KB 시스템 접수나 자동 전송을 뜻하지 않는다.
- 생성 행위는 tenant 감사 로그에 남긴다.
- 향후 실제 연계는 동일 계약을 소비하는 `BankConsultationHandoffProvider` 구현으로 추가한다.
  KB 상품, 채널 식별자, 인증과 접수 상태는 integration 리프에만 둔다.

## 결과

- KB 연계가 없어도 고객과 RM이 동일한 상담 자료를 공유할 수 있다.
- 핵심 계산과 규칙은 특정 금융기관에 종속되지 않는다.
- 현재 데모는 전송·접수·승인·한도 확정을 제공하지 않는다.
- 실제 연계 시 동의 철회, 재전송 멱등성, 접수 식별자와 상태 전이 저장소가 추가로 필요하다.

## 검증

- 같은 저장 분석과 대상 은행은 같은 `handoff_id`를 만든다.
- 패킷은 원문 문서를 포함하지 않으며 `transmission_performed=false`를 명시한다.
- 다른 tenant의 분석 ID로 패킷을 만들 수 없다.
- 생성 시 `consultation_handoff.prepare` 감사 이벤트가 남는다.
- 프론트는 동의 전 버튼을 비활성화하고 수동 인계임을 표시한다.
