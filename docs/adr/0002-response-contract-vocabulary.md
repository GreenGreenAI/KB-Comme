# ADR-0002: 응답 계약 어휘와 노출 부호

- 상태: 제안 (역할 A 승인 대기)
- 날짜: 2026-07-26
- 관련: MVP 아키텍처 정의서 §5.1, §7, §9.3, §10

## 배경

계산 계층은 `economic_offset`, `trade_net_exposure`를 쓰고, 정의서 §7 응답 계약은
`natural_hedge_amount`, `net_exposure`를 쓴다. 이름이 갈린 채로 합성 단계에 도달하면
계약 매핑이 암묵적으로 결정된다.

## 결정

### 1. 어휘를 2층으로 유지하고 매핑을 한 곳에 고정한다

내부 계산 어휘와 외부 응답 계약 어휘를 통일하지 않는다. `economic_offset`은
"전 구간 상계액이며 즉시 가용현금이 아니다"를 정확히 표현하므로 계산 계층에서
유지하고, 계약 경계에서만 §7 이름으로 투영한다.

| 내부 (`domain`/`tools`) | 외부 (§7) |
|---|---|
| `economic_offset` | `natural_hedge_amount` |
| `maturity_matched_amount` | `maturity_matched_amount` |
| `trade_net_exposure` | `net_exposure` |
| `peak_funding_gap` | `funding_gap` |
| `timeline` | `events` |

매핑은 `contracts/response.py` 한 곳에만 존재한다. 이 모듈은 이름만 바꾸며
재계산·반올림·근사를 하지 않는다. §9.3("합성 결과의 모든 수치가 도구 출력과
일치한다")의 수용 기준은 값 일치이지 이름 일치가 아니므로 이 분리는 규율 위반이
아니며, `tests/platform/test_response_contract.py`가 값 동일성을 검사한다.

### 2. `net_exposure`는 부호를 유지한다 (정의서 §5.1 개정 필요)

정의서 §5.1은 `잔여노출 = |Σ수취 - Σ지급|`로 절댓값을 규정하지만, **부호 있는 값을
채택하고 정의서를 개정한다.**

§5.3의 손익식은 다음과 같다.

```text
π(S, h) = π_0 + E·[ (1-h)(S - S_0) + h(F - S_0) ] - c·h·E·S_0
```

`E`가 절댓값이면 수입초과 기업에서 부호가 뒤집혀 헤지 방향이 반대로 산출된다.
§2.4가 초기 고객을 "수출입 병행 제조 중소기업"으로 확정했으므로 `E < 0`은 반드시
발생하는 정상 입력이다. 방향은 손실 방향을 결정하는 정보이므로 계약에서 보존한다.

### 3. 자연헤지 상계액에 만기 충족분을 병기한다 (정의서 §7 필드 추가)

§5.1은 `H_nat = min(Σ수취, Σ지급) [동일 통화·중첩 기간]`으로 중첩 기간을 조건에
포함하지만, 정의서 자신의 검증값(수입 30일 / 수출 90일 → 자연헤지 60,000)은 중첩
기간을 반영하지 않은 값이다. 정의서가 자체 모순 상태다.

MVP는 검증값과의 호환을 위해 `natural_hedge_amount`를 전 구간 기준으로 유지하되,
**그중 실제로 선행 수취가 충당하는 금액을 `maturity_matched_amount`로 병기한다.**
기준 시나리오는 다음과 같이 출력된다.

```text
natural_hedge_amount      60,000
maturity_matched_amount        0
funding_gap               40,000
```

상계액과 그것이 쓸모없다는 사실이 같은 블록에 함께 나온다. §10의 "합성 단계에서
수치 재서술" 위험을 서술 규칙이 아니라 계약 구조로 막는다.

### 4. 동일 일자에서는 지급을 먼저 정산한다

같은 날짜의 사건 순서를 `(결제일, 지급 우선, case_id)`로 고정한다. 지급 우선은
자금공백과 만기 충족분 양쪽에서 보수적인 값을 낳는다. 당일 수취가 자금공백을
완화하지 않고, 선행하지 않은 수취가 지급을 충당한 것으로 계산되지 않는다.

## 결과

- `CurrencyExposure`에 `maturity_matched_amount` 추가 — `domain/` 변경이므로 역할 A 승인 필요
- 정의서 §5.1(부호, 중첩 기간)과 §7(필드 추가) 개정 필요. 정의서 §11의 "상위 문서 개정
  필요 사항" 목록에 2건을 추가한다.
- 워커는 자기 출력을 §7 이름으로 맞출 필요가 없다. 계약 정렬은 경계 모듈의 책임이다.
