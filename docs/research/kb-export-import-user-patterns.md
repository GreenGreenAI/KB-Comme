# KB 수출입금융 유저 유형별 활용 패턴

## 1. 목적

이 문서는 공개자료에서 확인한 KB 수출입금융 상품·서비스를 실제 기업의 상황과 연결해
`유저 유형 × 활용 케이스` 형태로 정리한다. 향후 다음 작업의 기준 초안으로 사용한다.

- `user_profile` 분류 체계 설계
- 유형별 우선 노출 데이터·상품·행동 추천 정의
- BANKTRASS, Trade Info, 무역보험 연계 등 내부·외부 시스템 조회 요구사항 도출
- 프롬프트와 에이전트 정책 설계

이 문서의 유형은 상호 배타적 고객 세그먼트가 아니다. 한 기업이 거래 단계, 결제 방식,
조달 구조와 리스크에 따라 여러 유형에 동시에 해당할 수 있다.

## 2. 유저 유형 × 활용 케이스

| 유저 유형 | 주요 니즈·상황 | 대표 활용 상품·서비스 | 에이전트가 지원해야 할 액션 |
|---|---|---|---|
| 기존 수출 중소·중견기업 | 최근 1년 수출실적이 있고 운전자금과 환율 리스크가 부담되는 제조·무역사 | 수출기업 국내 운전자금 외화대출, 수출기업 우대대출, 수출환어음매입, 무역금융 | BANKTRASS 기반 수출실적 확인, 외화·원화 자금 믹스 추천, 환율 시나리오별 상환비용 시뮬레이션, 필요 서류 체크리스트 생성 |
| 잠재 수출기업 | 아직 수출실적은 없지만 수출계약서 또는 신용장을 보유하고 초기 자금이 부족한 기업 | 수출기업 우대대출의 잠재 수출기업 지원, 보증서 기반 대출, 통관·관세 상담, 수출패키지 우대금융 상담 | 수출계약·L/C 등 증빙을 기준으로 이용 가능 상품 필터링, 무역보험·보증 연계 시뮬레이션, 최초 수출 프로세스의 통관·선적·결제 단계 안내 |
| 소재·부품·장비 또는 방산 수입기업 | 핵심 소재·장비를 해외에서 조달해야 하고 결제기간을 늘리고 싶은 기업 | 수입신용장, KB Payment Usance, 협약 수입보험(글로벌공급망) | 업종·국가·결제조건에 따른 적정 유산스 기간 제시, 보험·보증 필요 여부 검토, 신용장 조건 가이드, 예상 이자·수수료 계산 |
| 분쟁·고위험 지역 진출 수출입기업 | 중동 등 지정학적 리스크가 높은 지역과 거래하며 환율·결제 리스크가 큰 기업 | 수출기업 국내 운전자금 외화대출, 수입신용장 수수료 감면, 해외송금 수수료 면제, 환율 우대 등 외환 금융 지원 프로그램 | 거래 국가·통화·만기에 따른 리스크 수준 산정, 우대 프로그램 매칭, L/C·송금 방식별 비용 비교, 선물환 등 헤지 전략 추천 |
| 대기업·중견 수출기업의 해외 구매자 금융 | 해외 바이어에게 장기 외상 조건을 제공하고 싶지만 자기 자금이 묶이는 대형 수출기업 | KB 글로벌 수출지원금융, 무역보험공사 단기수출보험(구매자신용), 해외지점 대출 | 선적·수출신고 정보의 Trade Info 연계, 수출채권 조기 현금화 구조 설명, 해외 바이어 신용도와 보험 가능 여부 확인, 상환기간·금리 조건 설계 보조 |
| 스타트업·초기 수출기업 | 인력이 적고 무역실무 경험이 부족해 무역·관세·계약·결제 구조 설계에 어려움이 있는 기업 | 수출입통관상담서비스, 수출패키지 우대금융, SME 전담 지점장 상담, 바로ERP 연계 | 품목·HS코드·목적국에 따른 관세·통관 체크포인트와 필요 라이선스·인증 안내, 상담 예약 지원, ERP 데이터 기반 금융상품 추천 |
| 협력사·서플라이체인 기업 | 주력 수출기업의 1·2차 협력사로서 간접 수출실적과 자금 압박이 있는 기업 | 협력사 대상 외환·수수료 우대 프로그램, 운전자금 대출, 보증연계 금융 | 주력기업·협력사 관계에 따른 협약 프로그램 자격 판별, 간접 수출실적을 반영한 한도 추정, 실적·신용등급 기반 금리 시뮬레이션 |
| 환리스크 민감 기업 | 마진이 얇고 환율 변동에 민감하며 재무팀이 FX 전략을 적극 운용하는 기업 | KB Star FX 플랫폼, 환율 포럼·컨설팅, 외화대출과 헤지 상품의 조합 | 매출·원가 통화구조에 따른 자연헤지 정도 계산, 환율 시나리오별 손익 시각화, 적정 헤지 비율·만기 제안, 포럼·컨설팅 연결 |

## 3. 유형 판별에 필요한 `user_profile` 정보

유저 유형은 단일 라벨보다 복수 태그와 신뢰도로 표현하는 것이 적합하다. 최소 입력 후보는
다음과 같다.

| 분류 영역 | 주요 필드 예시 | 판별 목적 |
|---|---|---|
| 기업 기본정보 | 기업 규모, 업종, 주요 품목, 설립연도, 임직원 수 | 중소·중견·대기업, 스타트업, 소재·부품·장비·방산 여부 판별 |
| 무역 단계 | 수출실적 유무, 최근 1년 수출액, 수출계약·L/C 보유 여부 | 기존 수출기업과 잠재·초기 수출기업 구분 |
| 거래 구조 | 수출·수입 구분, 목적국·조달국, 거래 통화, 결제 방식, 결제 만기 | 수출채권 금융, 수입 L/C·유산스, 고위험 국가 거래 여부 판별 |
| 자금 수요 | 필요 금액, 필요 시점, 자금 용도, 회수·상환 예정일 | 운전자금, 수입대금, 구매자 금융 등 금융 목적 판별 |
| 공급망 관계 | 주력기업, 협력사 단계, 납품계약, 간접 수출실적 | 협력사·서플라이체인 유형과 협약 프로그램 가능성 판별 |
| 환리스크 | 매출·원가 통화, 예상 외화 현금흐름, 기존 헤지 비율·수단 | 자연헤지 수준과 환리스크 민감도 판별 |
| 실행 역량 | 무역 담당 인력, ERP 사용 여부, 관세·통관 경험, 상담 필요도 | 스타트업·초기 수출기업에 필요한 안내 수준 결정 |

권장 분류 결과 예시는 다음과 같다.

```json
{
  "primary_type": "existing_exporter_sme",
  "secondary_types": ["fx_sensitive", "supply_chain_supplier"],
  "confidence": 0.82,
  "evidence": [
    "최근 12개월 수출실적 존재",
    "수출대금은 USD, 원재료 대금은 JPY",
    "주력 수출기업의 1차 협력사"
  ],
  "missing_information": ["기존 헤지 비율", "협약 프로그램 가입 여부"]
}
```

## 4. 유형별 우선 노출 원칙

에이전트는 상품명부터 나열하기보다 `판단에 필요한 데이터 → 적용 가능한 금융 구조 → 다음
행동` 순서로 안내한다.

| 유형 | 우선 노출 데이터 | 우선 금융·서비스 후보 | 우선 행동 추천 |
|---|---|---|---|
| 기존 수출기업 | 수출실적, 채권 회수일, 통화별 현금흐름 | 운전자금, 수출환어음매입, 무역금융, 외화대출 | 실적 확인 → 자금 공백 계산 → 원화·외화 조달 비교 → 서류 준비 |
| 잠재·초기 수출기업 | 계약서·L/C, 첫 선적일, 품목·목적국 | 우대대출, 보증연계, 통관상담, 수출패키지 | 증빙 확인 → 자격·보증 검토 → 최초 수출 단계 안내 → 상담 연결 |
| 수입기업 | 수입계약, L/C 조건, 결제일, 조달국 | 수입신용장, Payment Usance, 수입보험 | 결제 구조 확인 → 유산스 기간 비교 → 비용 계산 → 조건·서류 점검 |
| 고위험 지역 거래기업 | 국가, 통화, 결제방식, 만기, 제재·보험 정보 | 외환 지원 프로그램, L/C, 보험·보증, 헤지 | 국가·결제 리스크 확인 → 거래방식 비교 → 헤지·보험 검토 → 전문가 확인 |
| 해외 구매자 금융 수요기업 | 바이어, 수출채권, 선적·신고 정보, 희망 신용기간 | 글로벌 수출지원금융, 구매자신용 보험, 해외지점 대출 | 바이어·보험 가능성 확인 → 현금화 구조 설계 → 기간·비용 비교 → 상담 연결 |
| 협력사 | 주력기업 관계, 납품·간접 수출실적, 자금 공백 | 협약 우대, 운전자금, 보증연계 | 관계 증빙 확인 → 협약 자격 판별 → 한도·금리 추정 → 필요 서류 준비 |
| 환리스크 민감 기업 | 통화별 매출·원가, 만기별 노출, 기존 헤지 | Star FX, 외화대출, 선물환 등 헤지 수단 | 자연헤지 계산 → 시나리오 손익 비교 → 헤지 비율·만기 검토 → 컨설팅 연결 |

## 5. 시스템 조회 요구사항 초안

아래 항목은 실제 KB 내부 API 계약을 확인한 결과가 아니라, 에이전트가 위 활용 케이스를
지원하기 위해 필요한 논리적 조회 요구사항이다.

| 시스템·연계 | 필요한 조회·입력 | 기대 결과 | 주요 적용 유형 |
|---|---|---|---|
| BANKTRASS | 사업자 식별정보, 조회기간, 직접·간접 수출 구분 | 최근 수출실적, 품목·국가·통화별 실적, 실적 증빙 상태 | 기존 수출기업, 협력사 |
| Trade Info | 선적정보, 수출신고번호, 거래처, 결제조건 | 선적·신고 현황, 수출채권과 거래의 연결 정보 | 해외 구매자 금융, 기존 수출기업 |
| 상품 카탈로그 | 기업 유형, 자금 용도, 통화, 기간, 담보·보증 여부 | 적용 가능 상품 후보, 공개 조건, 필수 서류와 상담 채널 | 전체 유형 |
| 무역보험·보증 연계 | 국가, 바이어, 거래금액, 결제방식·기간, 수출입 구분 | 보험·보증 후보, 가입 가능성, 필요 심사와 추가 정보 | 잠재 수출기업, 고위험 지역, 구매자 금융, 수입기업 |
| 환율·FX | 통화쌍, 현물·선물환율, 기간, 환전·헤지 우대 정보 | 환율 시나리오, 조달·상환 비용, 헤지 대안 | 기존 수출기업, 고위험 지역, 환리스크 민감 기업 |
| 기업·협약 정보 | 기업 식별정보, 업종, 주력기업·협력사 관계, 협약 코드 | 협약 프로그램 자격, 우대 적용 가능성 | 협력사, 소재·부품·장비·방산 기업 |
| 상담·채널 | 상담 주제, 기업 소재지, 희망 일시, 필요 전문분야 | 적정 영업점·RM·전문가, 예약 가능 시간, 전달 패킷 | 전체 유형 |

내부 연계가 제공되지 않는 단계에서는 조회 성공을 가장하지 않고 `manual` 또는
`unavailable` 상태를 명시한 뒤, 사용자가 내려받거나 상담 시 전달할 수 있는 준비 패킷을
생성한다.

## 6. 에이전트 정책 설계 원칙

1. **복수 유형 허용**: 하나의 주 유형과 0개 이상의 보조 유형을 함께 유지한다.
2. **근거 기반 분류**: 각 유형에는 판별에 사용한 사용자 입력·문서·조회 결과를 연결한다.
3. **불확실성 표시**: 상품 자격, 금리, 한도, 보험 가능 여부를 확정적으로 표현하지 않는다.
4. **데이터 최소화**: 추천과 조회에 필요한 정보만 요청하고 외부 전달에는 사용자 동의를 받는다.
5. **리스크 우선 처리**: 제재, 고위험 국가, 보험·보증 필요성, 문서 불일치는 상품 추천보다 먼저 확인한다.
6. **비용의 동일 기준 비교**: 금리뿐 아니라 환율, 수수료, 보험료와 기간을 포함한 총비용으로 비교한다.
7. **행동 가능한 결과 제공**: 모든 결과에는 다음 행동, 필요 서류, 확인할 질문과 상담 경로를 포함한다.
8. **시스템 상태 구분**: 공개정보, 사용자 제공정보, 내부 조회정보와 모델 추정을 명확히 구분한다.

## 7. 검증 상태와 유의사항

- 이 문서는 공개자료를 바탕으로 만든 제품·정책 설계용 초안이다.
- 상품 명칭, 지원 대상과 우대 조건은 변경될 수 있으며 실제 적용 여부는 KB국민은행과 관계기관의 최신 기준 및 개별 심사를 따라야 한다.
- 언론 기사와 블로그 출처가 포함되어 있으므로, 프롬프트·규칙·상품 카탈로그의 운영 기준으로 승격하기 전에 KB 및 관계기관 공식 자료로 교차 검증해야 한다.
- BANKTRASS, Trade Info와 무역보험 연계의 실제 조회 필드, 권한, 동의 절차와 응답 계약은 별도 내부 협의가 필요하다.
- 에이전트의 계산·추천 결과는 금융상품 가입 가능 여부, 신용 승인 또는 확정 견적을 의미하지 않는다.
