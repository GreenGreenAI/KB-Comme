# TradeFlow KB AI Challenge 발표 슬라이드 텍스트·내러티브

## 1. 발표가 수행해야 하는 역할

심사위원이 발표를 모두 확인한 뒤 다음 내용을 이해하도록 한다.

- 수출입기업은 환위험만이 아니라 유동성, 신용, 국가, 문서, 계약·결제, 물류, 규정,
  금융조달과 실행·운영 위험을 하나의 거래 안에서 함께 관리해야 한다.
- 각각의 위험은 서로 독립적이지 않다. 계약조건이나 선적 일정 하나의 변화가 자금 공백,
  환노출 기간, 미수 가능성, 보험 적격성, 필요서류와 금융조치에 연쇄적으로 영향을 준다.
- TradeFlow의 본질은 특정 위험 계산기가 아니라, 확인된 거래 맥락과 근거를 공통 입력으로 받아
  여러 위험 모듈과 시나리오, 실행 대안을 연결하는 `무역위험 의사결정 기반`이다.
- 현재 데모는 이 기반 위에서 구현 완성도가 가장 높은 `유동성 위험`과 `환위험`을 대표 사례로
  증명한다.
- 향후 위험별 데이터, 규칙팩, 분석 모듈과 외부 어댑터가 확보되면 동일한 의사결정 계약을
  유지하면서 나머지 위험으로 확장할 수 있다.

발표의 중심 문장은 다음과 같다.

> **TradeFlow는 수출입 거래의 사실과 근거를 하나의 맥락으로 연결하고, 거래조건이나 외부
> 상황이 바뀌었을 때 여러 무역위험과 필요한 행동이 어떻게 달라지는지를 비교하는 확장형
> 무역금융 의사결정 AI다.**

주의할 점은 `데이터만 있으면 자동으로 확장된다`고 표현하지 않는 것이다. 실제 확장에는 다음
네 가지가 함께 필요하다.

```text
위험별 데이터
+ 공식 규정·금융조건을 구조화한 규칙팩
+ 계산·조회·검증을 수행할 위험 모듈
+ 도메인 전문가 검증과 운영 승인
```


## 2. 슬라이드를 관통하는 내러티브

### 1막 — 수출입 거래에는 여러 위험이 동시에 존재한다

기업은 한 건의 거래에서도 자금, 환율, 바이어 신용, 국가 상황, 서류 하자, 결제조건, 물류,
규정, 금융조달과 실행 일정을 함께 판단해야 한다. 그러나 이 정보는 계약서, ERP, 시장 데이터,
공공기관, 보험기관과 은행 상담에 흩어져 있다.

### 2막 — 위험은 서로 연결되어 있지만 업무는 분리돼 있다

수취일이 30일 늦어지면 자금 공백 기간과 환노출 기간이 함께 늘어난다. 지연의 원인이 바이어
신용이나 국가 송금 제한이라면 보험과 금융조치도 바뀐다. 그럼에도 현장에서는 각 위험을 별도
도구와 담당자가 처리해 변화의 연쇄 영향을 추적하기 어렵다.

### 3막 — TradeFlow는 위험을 관통하는 공통 기반을 제공한다

TradeFlow의 목표는 거래 사실, 문서, 외부 데이터와 확인 상태를 공통 거래 맥락으로 만들고,
위험별 모듈이 같은 사실과 근거를 사용하게 하는 것이다. 현재 데모의 거래 맥락에는 사용자
확인 정보와 공식 데이터가 연결되며, 문서 추출·확인 결과는 별도로 보존된다. 문서에서 확인한
값을 분석 입력에 자동 반영하는 연결은 확장 대상이다. 결과 변화는 Decision Delta로 비교하고,
상담용 Decision Passport가 현재 지원하는 결과와 근거·미확인 조건·행동을 보존한다.

### 4막 — 현재 데모는 유동성·환위험으로 기반의 작동을 증명한다

현재 구현은 사용자가 확정한 결제일을 기준으로 자금 공백·자연헤지·만기상계·잔여 환노출과
환율 시나리오를 계산한다. Next Decisive Question, Decision Delta와 Passport를 통해 정보
보완부터 상담 준비까지 연결한다. 이는 전체 위험 플랫폼 중 첫 번째 완성된 수직 흐름이다.

### 5막 — 동일한 계약 위에서 나머지 위험 모듈로 확장한다

신용·국가·문서·계약·물류·규정·금융조달·운영 위험도 동일한 입력·출력 계약을 사용한다.
각 영역에 공식 데이터와 규칙팩, 분석 모듈과 전문가 승인을 연결하면 위험 간 영향을 하나의
Decision Twin에서 비교할 수 있다.

### 차별점 파트의 논문형 설명 구조

차별점은 개별 기능을 병렬로 나열하지 않고 `핵심 주장 → 세 가지 기여점 → 작동 사례 → 구현
증거` 순서로 설명한다.

```text
Overview         슬라이드 4    세 가지 차별점을 한 흐름으로 제시
Contribution 1   슬라이드 5    여러 위험이 공유하는 하나의 거래 맥락
Contribution 2   슬라이드 8~9  판단을 바꾸는 질문과 변경 전후 비교
Contribution 3   슬라이드 10   근거·불확실성·행동을 보존하는 Passport
Generalization   슬라이드 11~13 같은 계약으로 다른 위험에 확장하는 방식
Evidence         슬라이드 14~16 실제 구현 구조·범위·검증 결과
```

각 상세 슬라이드는 새로운 기능을 추가로 소개하는 것이 아니라, Overview에서 제시한 차별점이
어떤 입력을 받아 무엇을 처리하고 어떤 사용자 가치를 만드는지를 증명한다.


## 3. 슬라이드별 내용

### 슬라이드 1. 표지

#### 제목
TradeFlow

#### 부제
수출입 거래의 위험과 금융조치를 연결하는 의사결정 AI

#### 화면 문구
흩어진 거래 사실과 위험 신호를 하나의 맥락으로 연결하고,
시나리오별 판단 근거와 다음 행동을 제공합니다.

Trade Risk Decision Foundation

#### 발표 설명
TradeFlow는 환위험 하나만을 다루는 계산기가 아닙니다. 한 건의 수출입 거래에서 발생하는 여러
위험을 같은 거래 사실과 근거 위에서 분석하고, 조건 변화가 필요한 금융조치와 행동을 어떻게
바꾸는지 설명하는 확장형 의사결정 기반입니다.

#### 다음 슬라이드 연결
수출입기업이 실제로 함께 판단해야 하는 위험부터 보겠습니다.


### 슬라이드 2. 수출입 거래의 10대 위험

#### 제목
한 건의 수출입 거래에는 열 가지 위험이 동시에 존재합니다

#### 화면 문구
1. 유동성 위험       결제일에 돈이 부족한가?
2. 환위험            환율 변화가 마진을 훼손하는가?
3. 신용위험          바이어가 대금을 지급하지 않을 수 있는가?
4. 국가위험          송금 제한·전쟁·제재·정치 불안이 있는가?
5. 문서위험          L/C·선적서류 하자로 지급이 거절될 수 있는가?
6. 계약·결제위험     Incoterms·D/A·O/A 조건이 불리하지 않은가?
7. 물류위험          선적 지연·파손·보험 공백이 있는가?
8. 규정위험          외국환 신고·수출통제·관세·인증 문제가 있는가?
9. 금융조달 위험     필요한 대출·보증·보험과 한도를 확보할 수 있는가?
10. 실행·운영 위험   신청·송금·만기·사후관리를 놓치지 않는가?

#### 화면 구성
열 개의 카드를 만들지 않는다. 거래 흐름을 중심에 두고 위험을 다음 네 묶음으로 배치한다.

```text
거래 이전       계약·신용·국가·규정
거래 실행       문서·물류·실행·운영
결제 시점       유동성·환위험
대응 수단       금융조달·보험·보증
```

#### 발표 설명
이 위험들은 개별 체크리스트가 아닙니다. 계약 이전부터 대금 회수 이후까지 같은 거래에 계속
영향을 주며, 한 영역의 변화가 다른 영역의 판단을 바꿉니다.

#### 다음 슬라이드 연결
실제 거래에서는 위험 하나의 변화가 어떻게 연쇄적으로 전파되는지 보겠습니다.


### 슬라이드 3. 위험의 연쇄성

#### 제목
계약조건 하나의 변화가 여러 위험과 행동을 함께 바꿉니다

#### 화면 문구
수출대금 결제조건
D+60 → D+90
        ↓
유동성 위험
자금 공백 기간 +30일
        ↓
환위험
환노출 유지기간 +30일
        ↓
신용·국가위험
지연 원인과 회수 가능성 확인
        ↓
보험·금융조달
보장 가능 여부·필요 금융기간 재검토
        ↓
실행·운영
신청서류·송금·만기 일정 변경

#### 하단 결론
위험은 분리돼 있지 않지만, 현재 업무와 정보는 분리돼 있습니다.

#### 발표 설명
결제조건이 30일 늘어났다는 사실은 단순히 날짜 하나가 바뀐 것이 아닙니다. 필요한 자금 기간과
환노출 기간이 늘고, 지연 원인이 바이어나 국가에 있다면 보험과 조달 판단, 실행 일정까지 달라질
수 있습니다. TradeFlow는 이 연쇄 영향을 하나의 거래 안에서 추적하는 것을 목표로 합니다.

#### 구현 상태
목표 통합 시나리오. 현재 자동 구현은 유동성·환위험 일부에 한정된다.

#### 다음 슬라이드 연결
이 다양한 위험을 연결하는 TradeFlow만의 차별점을 먼저 세 가지로 요약하겠습니다.


### 슬라이드 4. TradeFlow 차별점 Overview

#### 제목
세 가지 구조가 하나의 무역 의사결정 흐름을 만듭니다

#### 화면 문구
차별점 ① 하나의 거래 맥락
계약·일정·통화·당사자를 연결하고 문서 확인 결과를 보존해
여러 위험이 공유할 거래 기반을 만듭니다.

차별점 ② 판단의 변화 추적
판단에 직접 영향을 주는 정보를 우선 확인하고,
조건 변경 전후의 금액·위험·행동만 비교합니다.

차별점 ③ 근거에서 실행까지
계산·규칙·출처·불확실성과 다음 행동을 보존해
상담과 후속 업무로 이어갑니다.

#### 하단 결론
하나의 거래 맥락 → 판단 변화 → 검증 가능한 행동

#### 화면 구성
세 개의 독립 기능 카드로 보이지 않게 한다. 왼쪽에서 오른쪽으로 이어지는 하나의 흐름으로
배치하고, 이후 상세 슬라이드에서도 ①·②·③ 번호와 동일한 색을 유지한다.

#### 발표 설명
TradeFlow의 차별점은 환율 계산, 문서 확인, 상품 추천을 각각 하나씩 더 제공하는 데 있지
않습니다. 흩어진 정보를 하나의 거래 맥락으로 만들고, 어떤 정보와 조건이 실제 판단을
바꾸었는지 계산하며, 그 근거와 다음 행동을 상담과 실행까지 이어주는 구조에 있습니다.
이제 세 가지 차별점이 현재 제품에서 어떻게 작동하는지 순서대로 보겠습니다.

#### 구현 상태
- 차별점 ①: 거래 맥락 일부 구현
- 차별점 ②: 유동성·환위험 범위에서 구현
- 차별점 ③: Passport와 상담 lifecycle 일부 구현

#### 다음 슬라이드 연결
첫 번째 차별점은 여러 위험을 하나의 거래 단위로 연결하는 공통 맥락입니다.


### 슬라이드 5. 차별점 ① — 하나의 거래 맥락

#### 제목
여러 위험이 같은 거래 사실과 근거를 공유합니다

#### 화면 문구
1. Trade Context
   기업·거래·계약·일정·통화·당사자

2. Evidence Layer
   사용자 확인·문서·공식 데이터·전문가 검토

3. Risk Modules
   계산·조회·규칙 판정·불확실성 상태

4. Scenario & Decision Delta
   조건 변경 전후의 위험·행동 비교

5. Action & Decision Passport
   대응 선택지·필요서류·근거·최종 판단 주체

#### 하단 결론
새로운 위험은 새로운 제품이 아니라, 같은 기반에 연결되는 모듈입니다.

#### 발표 설명
TradeFlow의 확장성은 위험 이름을 화면에 추가하는 데 있지 않습니다. 모든 위험이 같은 거래
사실, 출처, 상태, 시나리오와 행동 계약을 사용하도록 만든 구조에 있습니다. 위험별 데이터와
규칙팩, 분석 모듈을 이 계약에 연결하면 기존 질문·Delta·Passport 흐름을 재사용할 수 있습니다.

#### 구현 상태
- 현재 구현: Trade Context 일부, Evidence, 유동성·환위험 모듈, Delta, Passport
- 확장 기반: 위험 모듈 인터페이스와 외부 데이터 adapter 구조
- 목표: 위험 간 의존관계와 통합 시나리오 전파

#### 다음 슬라이드 연결
현재 데모는 이 공통 기반이 실제로 작동함을 두 개의 위험으로 증명합니다.


### 슬라이드 6. 현재 데모의 역할

#### 제목
현재 데모는 유동성·환위험으로 공통 기반의 작동을 증명합니다

#### 화면 문구
현재 데모 범위

유동성 위험
- 결제일별 외화 잔액
- 최대 자금 공백과 결제 이벤트 타임라인
- 보유 외화 반영

아닙니다. 정량 계산, 정보 보완, 변화 비교, 근거 보존과 수동 상담 준비를 실제 코드로 끝까지
증명하기에 가장 적합한 첫 번째 수직 흐름이기 때문입니다.

### 슬라이드 7. 계약조건이 만든 자금 공백

#### 제목
계약의 결제 일정 사이에 USD 60,000의 자금 공백이 생깁니다

#### 화면 문구
수입 거래                         수출 거래
2026.08.25                       2026.10.24
- USD 60,000                    + USD 100,000

최종 순유입                  USD 40,000
경제적 자연헤지              USD 60,000
만기상계                       USD 0

#### 발표 설명
거래 전체는 USD 40,000 흑자지만 수출대금이 들어오기 전에는 USD 60,000이 부족합니다.
기간 전체의 자연헤지와 실제 지급일에 사용할 수 있는 만기상계도 다릅니다. 현재 TradeFlow는
사용자가 확정한 결제일을 기준으로 날짜별 잔액, 최대 자금 공백, 자연헤지와 잔여 환노출을
직접 계산합니다. 60일은 화면에 표시된 두 결제 이벤트의 날짜 차이이며, 현재 별도의 공백
지속기간 지표로 반환되지는 않습니다.

#### 구현 상태
현재 구현. 상대일 계약 조항에서 결제일을 자동 도출하는 기능은 목표다.

#### 다음 슬라이드 연결
계산값을 보여주는 것만으로는 기업이 다음 결정을 내리기 어렵습니다.


### 슬라이드 8. 차별점 ②-1 — Next Decisive Question

#### 제목
판단에 직접 영향을 주는 정보를 규칙 기반 우선순위로 확인합니다

#### 화면 문구
Next Decisive Question

“현재 보유한 USD 잔액이 있습니까?”

이 질문이 먼저인 이유
- 필요 조달금액을 직접 변경
- 기업 담당자가 즉시 확인 가능
- 답변 전에는 자금 조달규모 확정 불가

#### 발표 설명
TradeFlow는 누락된 모든 정보를 같은 순서로 묻지 않습니다. 현재 구현은 USD 자금 공백이 있을
때 보유잔액을 먼저 확인하고, 이후에는 영향을 받는 판정 수와 미리 정의한 업무 우선순위에 따라
다음 질문을 정합니다. 모든 미확인 값을 가상으로 대입해 영향액을 최적화하는 방식은 아닙니다.
향후 신용위험에서는 바이어 식별정보, 문서위험에서는 지급 거절을 만드는 핵심 불일치가 같은
우선순위 계약에 연결될 수 있습니다.

이는 차별점 ②의 첫 단계입니다. 단순히 정보가 부족하다고 알리는 것이 아니라, 어떤 정보가
현재 판단을 실제로 바꾸는지 우선순위를 정합니다.

#### 구현 상태
현재 구현. 위험별 질문 확장은 해당 모듈과 규칙팩이 필요하다.

#### 다음 슬라이드 연결
사용자의 답변이 실제 결과를 어떻게 바꾸었는지 비교합니다.


### 슬라이드 9. 차별점 ②-2 — Decision Delta

#### 제목
새로운 정보가 바꾼 판단만 전후로 비교합니다

#### 화면 문구
확인된 정보
“현재 보유한 USD 잔액이 있습니까?” → USD 20,000 확인

Decision Delta에 표시되는 변화
최대 자금 공백      USD 60,000 → USD 40,000

표시되지 않는 지표
경제적 자연헤지 · 잔여 환노출
값이 바뀌지 않았으므로 Delta에서 제외

#### 발표 설명
보유 외화를 반영하면 지급일에 필요한 조달금액은 줄지만 계약의 금액과 일정은 바뀌지 않으므로
자연헤지와 잔여 환노출은 그대로입니다. Decision Delta는 전체 분석을 다시 나열하는 대신 실제로
바뀐 금액·상태·행동만 반환합니다. 현재 구현은 해결된 질문과 최대 자금 공백의 변화를 기록하며,
변하지 않은 자연헤지와 잔여 환노출은 Delta 결과에 포함하지 않습니다. 같은 비교 계약은 다른
위험 모듈에도 재사용할 수 있습니다.

Next Decisive Question이 무엇을 더 확인할지를 정한다면, Decision Delta는 그 답변이 판단을
어떻게 바꾸었는지 증명합니다. 질문과 변화 비교가 함께 작동하는 것이 차별점 ②입니다.

#### 구현 상태
현재 구현. 현재 Delta 범위는 자금 지표, 지원 후보 상태, 행동과 필요서류 중심이다.

#### 다음 슬라이드 연결
결정의 변화와 근거는 거래가 끝날 때까지 이어지는 패킷으로 보존됩니다.


### 슬라이드 10. 차별점 ③ — Decision Passport

#### 제목
계산 근거와 다음 행동을 하나의 거래 패킷으로 이어갑니다

#### 화면 문구
Decision Passport

거래 사실       누가 확인한 어떤 정보인가?
위험 결과       어떤 계산·조회·판정이 수행됐는가?
시나리오 변화   조건 변경으로 무엇이 달라졌는가?
규칙과 출처     어떤 버전과 공식 근거를 사용했는가?
미확인 조건     무엇을 누가 추가로 확인해야 하는가?
다음 행동       어떤 조치와 서류가 필요한가?
권한 경계       누가 최종 판단하고 승인하는가?

#### 발표 설명
현재 Passport는 거래 사실, 유동성 결과와 일부 금융지원·규정 후보를 수동 상담자료로 묶습니다.
향후 환율 시나리오·헤지 분석과 신용, 국가, 문서, 규정 모듈이 연결되면 같은 거래 패킷 안에
위험별 결과와 근거, 미확인 조건이 추가됩니다. 검토자는 생성형 AI의 문장만 믿는 대신 재현
가능한 사실과 계산, 규칙을 확인할 수 있습니다.

이 패킷은 분석 결과의 종착점이 아니라 상담과 후속 업무의 시작점입니다. 무엇을 근거로 어떤
판단을 했고, 무엇이 아직 불확실하며, 누가 다음 행동을 해야 하는지를 함께 보존하는 것이
차별점 ③입니다.

#### 구현 상태
현재 구현. 현재 상담용 Passport에는 거래 사실, 유동성 결과, 일부 금융지원·규정 후보,
Next Question·Delta, 문서 목록, 근거와 계산 버전이 포함된다. 환율 시나리오와 헤지 분석은
아직 상담용 Passport에 포함되지 않는다.

#### 다음 슬라이드 연결
다른 위험이 동일한 흐름에 어떻게 연결되는지 구조를 보겠습니다.


### 슬라이드 11. 위험 모듈의 확장 방식

#### 제목
위험별 데이터와 규칙을 연결하면 같은 의사결정 흐름을 재사용합니다

#### 화면 문구
공통 입력
Trade Context + Evidence
        ↓
위험 모듈 계약
analyze(context, evidence, scenario)
        ↓
공통 출력
status · findings · uncertainty · evidence IDs · actions
        ↓
공통 경험
Next Question · Decision Delta · Decision Passport

#### 위험 모듈 예시
Liquidity · FX · Credit · Country · Document · Contract
Logistics · Compliance · Funding · Operations

#### 발표 설명
확장 단위는 새로운 챗봇이나 별도 화면이 아니라 위험 모듈입니다. 각 모듈은 같은 거래 맥락을
입력받고, 상태·판정·불확실성·근거·행동이라는 공통 출력 계약을 반환합니다. 덕분에 질문,
변화 비교, 근거 보존과 상담 인계는 다시 만들지 않고 재사용할 수 있습니다.

#### 구현 상태
설계 방향. 일부 adapter·규칙·capability 구조는 존재하지만 10개 위험 모듈이 모두 구현된 것은 아니다.

#### 다음 슬라이드 연결
나머지 위험이 연결되면 사용자 경험이 어떻게 확장되는지 예시로 보겠습니다.


### 슬라이드 12. 신용·국가·문서·계약 위험 확장

#### 제목
외부 데이터가 연결되면 ‘무엇이 위험한가’에서 ‘무엇을 해야 하는가’로 이어집니다

#### 화면 문구
신용위험
바이어 식별·신용정보 → 미수 가능성 → 결제조건·보험·선수금 검토

국가위험
송금 제한·제재·정치위험 → 회수 경로 영향 → 보험·결제방식 변경

문서위험
L/C·선적서류 불일치 → 지급 거절 가능성 → 수정 요청·서류 보완

계약·결제위험
Incoterms·D/A·O/A 조건 → 비용·책임·회수기간 → 가격·조건 재협상

#### 발표 설명
이 영역에는 바이어 신용조회, 국가위험 데이터, UCP 600 규칙팩과 계약 조항 구조화가 필요합니다.
데이터를 연결하는 것만으로 충분하지 않고, 공식 근거를 해석하는 규칙과 전문가 검증이 함께
필요합니다. 연결 후에는 결과가 기존 Delta와 Passport에 같은 형식으로 들어갑니다.

#### 구현 상태
부분 기반 또는 미구현. 목표 확장 영역.

#### 다음 슬라이드 연결
물류·규정·금융조달·운영 위험도 동일한 구조로 연결됩니다.


### 슬라이드 13. 물류·규정·금융조달·운영 위험 확장

#### 제목
거래 실행과 사후관리까지 같은 위험 맥락을 이어갑니다

#### 화면 문구
물류위험

확장합니다. 필요한 데이터와 기관 연계가 확보되면 동일한 거래 타임라인 안에서 위험 신호와
기한, 담당자, 조치를 연결할 수 있습니다.

#### 구현 상태
일부 다음 행동·상담 lifecycle 기반 구현. 위험별 실제 연계는 목표 영역.

#### 다음 슬라이드 연결

### 슬라이드 14. 현재 구현 구조

#### 제목
거래를 입력하면 계산부터 상담 준비까지 한 흐름으로 이어집니다

#### 화면 문구
1. 거래를 이해합니다
수출·수입 방향, 금액, 통화, 결제일과 보유 외화를 한 거래로 정리
        ↓
2. 필요한 돈과 환위험을 계산합니다
언제 얼마가 부족한지, 얼마나 상계되고 환율에 노출되는지 계산
        ↓
3. 판단에 직접 영향을 주는 정보를 확인합니다
보유 외화처럼 조달금액과 다음 행동을 바꾸는 질문을 먼저 제시
        ↓
4. 답변 전후의 차이를 보여줍니다
달라진 금액·상태·행동과 해결된 질문만 비교
        ↓
5. 근거와 다음 행동을 넘겨줍니다
확인된 사실·계산·출처·미확인 조건·필요서류를 상담자료로 보존
        ↓
상담 패킷을 내려받고 수동 전달 여부와 상담 경과를 사용자가 기록

숫자는 코드가 계산합니다. LLM 연결 시 검증된 결과만 설명합니다

#### 발표 설명
현재 구현은 분석 결과 한 장을 만드는 데서 끝나지 않습니다. 사용자가 거래조건을 입력하면
먼저 날짜별 지급과 수취를 정리해 자금 공백과 환노출을 계산합니다. 그다음 현재 판단을 바꿀
미확인 정보를 규칙 기반 우선순위로 질문하고, 사용자의 답변을 반영해 결과를 다시 계산합니다. 전후
결과에서는 실제로 바뀐 항목만 보여주고, 사용한 사실과 근거, 아직 확인할 사항과 필요서류를
하나의 상담자료로 묶습니다. 사용자는 패킷을 내려받아 담당자에게 수동 전달하고, 전달 여부와
상담 경과를 직접 기록하며 이전 분석 이력도 확인할 수 있습니다. 현재 은행 시스템으로 상담을
요청하거나 상태를 자동 수신하지는 않습니다.

#### 파트별로 실제 구현한 방식 — 발표자 참고
- **거래 이해:** 여러 수출입 건의 방향·금액·통화·결제일과 기초 외화잔액을 공통 거래 형식으로
  저장하고, 입력 누락과 형식을 분석 전에 검사한다.
- **자금 판단:** 지급일과 수취일 순서대로 외화 잔액을 쌓아 어느 날 얼마가 부족한지를 계산하고,
  최대 부족액과 날짜별 결제 이벤트를 반환한다. 별도의 공백 지속기간 지표는 아직 없다.
- **환위험 판단:** 같은 통화의 수취·지급을 전체 금액과 실제 만기 기준으로 각각 상계하고,
  남은 노출과 환율 변화 시 손익을 계산한다. 시장 시나리오, 기준이익·손익 하한과 이용 가능한
  확인 헤지조건이 갖춰진 경우에만 최소 헤지비율을 계산한다.
- **판단 보완:** USD 보유잔액, 영향을 받는 판정 수와 미리 정의한 업무 우선순위를 기준으로
  Next Decisive Question을 정하고, 답변 반영 전후의 실제 변경값을 Decision Delta로 생성한다.
- **근거와 상담:** 문서 업로드·기본 추출·사용자 확인 결과, 규칙 출처, 계산 결과, 미확인 조건과
  필요서류를 상담용 Decision Passport에 담는다. 패킷은 자동 전송하지 않으며, 수동 전달과
  상담 경과를 사용자가 기록하고 분석 이력과 함께 저장한다.
- **AI의 역할:** 금액과 지원·규정 후보 상태는 코드가 생성한다. LLM이 연결된 환경에서는 확정된
  수치만 설명하며, 연결되지 않거나 검증에 실패하면 규칙 기반 설명을 사용한다.

#### 기술 매핑 — 발표자 참고
- 사용자 경험: React 거래 입력·분석·문서·상담 화면
- 처리 경로: FastAPI 분석·문서·상담 API
- 계산: 결제일 원장, 자금 공백, 자연헤지, 만기상계, 환노출과 헤지 엔진
- 보존: 버전형 출처·규칙, 조직별 분석 이력, 암호화 문서와 감사로그

#### 현재 연결이 끊긴 지점
- 문서에서 확인한 필드가 거래 원장과 분석 요청으로 자동 반영되지 않음
- 상대일 계약조건과 Incoterms를 결제 이벤트로 자동 변환하지 않음
- 위험 간 의존관계를 자동 전파하는 통합 Scenario Graph가 없음

바이어와 국가 데이터로 회수 가능성과 보험 판단을 보완합니다. 이후 선적과 규정 이벤트를 같은
거래 일정에 연결하고, 금융기관 연계를 통해 분석 결과가 실제 상담과 신청, 만기관리로 이어지게
합니다. 마지막 단계에서는 한 조건의 변화가 여러 위험과 금융조치를 어떻게 바꾸는지 한 번에
비교합니다.

### 슬라이드 17. 결론

#### 제목
현재 데모는 두 위험을 보여주지만, 기반은 거래 전체를 향합니다

#### 화면 문구
오늘 증명한 것
유동성 위험 + 환위험
        ↓
공통 의사결정 기반
Context · Evidence · Risk Module · Scenario · Delta · Passport
        ↓
확장할 위험
신용 · 국가 · 문서 · 계약 · 물류 · 규정 · 금융조달 · 실행·운영

TradeFlow
하나의 거래, 하나의 맥락, 연결된 위험과 행동

#### 발표 설명
TradeFlow의 현재 데모는 자금 공백과 환위험을 직접 계산하고, 결과를 바꾸는 정보와 근거를
상담자료로 연결합니다. 그러나 제품의 목적은 두 위험에 머무르지 않습니다. 같은 거래 맥락과
근거, 시나리오, 변화 비교와 행동 계약 위에 다른 위험 모듈을 연결해 수출입 거래 전체의
의사결정을 지원하는 기반으로 확장하는 것이 목표입니다.


## 4. 전체 발표를 한 문장으로 연결한 버전

수출입기업은 유동성·환위험뿐 아니라 신용, 국가, 문서, 계약·결제, 물류, 규정, 금융조달과
실행·운영 위험을 한 거래 안에서 함께 판단해야 하지만, 현재 정보와 업무는 기관과 시스템별로
분리돼 있습니다. TradeFlow는 현재 사용자 확인 정보와 공식 데이터를 공통 거래 맥락에 연결하고,
문서 추출·확인 결과는 별도로 보존합니다. 문서 확인값의 분석 자동 반영과 위험 간 통합 시나리오는
확장 대상입니다. 현재 데모는 입력한 거래를
결제일 순서의 현금흐름으로 바꾸고, 자금 공백·자연헤지·잔여 환노출과 환율 시나리오를 코드로
직접 계산합니다. 그 결과에서 Next Decisive Question,
Decision Delta, Decision Passport를 생성해 정보 보완부터 상담 준비까지 이어지는 수직 흐름을
증명합니다. LLM이 연결된 환경에서는 구조화된 결과의 설명만 담당하며, 연결되지 않아도 규칙
기반 설명으로 동일한 계산 결과를 제공합니다. 향후 바이어·국가·물류·규정·
금융기관 데이터, 공식 규칙팩, 위험 모듈과 전문가 승인이 확보되면 같은 의사결정 계약을 유지한 채
나머지 위험으로 확장하고, 조건 변화가 여러 위험과 금융조치에 미치는 연쇄 영향을 하나의 거래
Decision Twin에서 비교합니다.


## 5. 발표 중 일관되게 사용할 핵심 용어

- **Trade Context:** 기업, 거래, 계약, 일정, 통화, 당사자와 확인 상태를 연결한 공통 거래 맥락
- **Evidence Layer:** 사용자 확인, 문서, 공식 데이터, 규칙 출처와 전문가 검토 이력을 보존하는 계층
- **Risk Module:** 공통 거래 맥락을 받아 특정 위험의 상태·판정·불확실성·근거·행동을 반환하는 모듈
- **분석 시나리오:** 기준 거래에서 결제조건, 일정, 환율, 바이어·국가 상태 등 하나 이상의
  조건을 바꾸고 위험과 필요한 행동의 변화를 비교하는 분석 조건
- **경제적 자연헤지:** 동일 통화 수출 수취액과 수입 지급액을 전체 기간 기준으로 상계할 수 있는 금액
- **만기상계:** 지급일까지 실제 수취한 외화를 해당 지급에 사용할 수 있는 금액
- **외화 자금 공백:** 날짜별 누적 외화 잔액이 음수가 될 때의 부족액이며, 현재 직접 제공하는
  집계값은 최대 부족액과 결제 이벤트 타임라인
- **잔여 환노출:** 수출입 금액을 상계한 후에도 환율 변화에 노출되는 순외화 금액
- **Next Decisive Question:** 보유 외화, 영향을 받는 판정 수와 업무 우선순위를 기준으로 먼저
  확인하도록 선택한 미확인 정보
- **Decision Delta:** 정보·조건 변경 전후에 실제로 바뀐 위험·금액·상태·행동만 보여주는 비교 결과
- **Decision Passport:** 현재 거래 사실, 유동성 결과, 지원·규정 후보, 질문·Delta, 문서 목록,
  근거와 계산 버전을 담는 수동 상담 패킷. 환율 시나리오와 헤지 분석 연결은 확장 대상
- **Decision Experience:** 질문, 변화 비교, 수동 상담 패킷과 사용자가 기록한 경과를 하나의
  의사결정 흐름으로 묶은 사용자 경험 계층
- **Scenario Graph:** 한 조건의 변화가 여러 위험과 행동에 전파되는 의존관계를 표현할 목표 구조이며 현재 미구현
- **Trade Deal Decision Twin:** 조건 변화가 여러 위험과 실행 대안에 미치는 영향을 거래 단위로 재계산하는 목표 구조
- **KB Adapter:** 공식 계약과 API 명세 확보 후 상담자료 전송과 은행 상태 연계를 담당하는 외부 인터페이스


## 6. 현재 구현과 확장 가능성의 표현 경계

- 현재 서비스가 10개 위험을 모두 자동 분석한다고 표현하지 않는다.
- 현재 데모가 유동성·환위험에 집중하지만 제품 비전도 두 위험에 한정된다고 표현하지 않는다.
